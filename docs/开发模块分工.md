# 奇迹塔防开发模块分工

> 目标：让不同线程或不同 Agent 可以各管一块，同时保持项目一致性、稳定性和可集成性。

## 总体原则

当前阶段先把一个稳定可玩的基础塔防切片做好，不急着扩展七大纪元。

- 主体线程负责方向、集成、测试和最终合并。
- 分支线程只负责一个边界清晰的模块。
- 分支线程可以读全项目，但写文件时应尽量限制在自己的模块目录。
- `game_manager.gd`、`game.tscn`、`project.godot` 属于高耦合文件，默认由主体线程或经过主体确认后修改。
- 每次做完一小块都运行 Godot headless 校验。
- 如果一个需求会跨越两个以上模块，先在主体线程拆任务，再分给分支。

## 推荐线程结构

### 1. 主体线程：集成与核心稳定性

职责：

- 决定当前版本目标和优先级。
- 维护项目结构、模块接口和基础流程。
- 合并分支成果，处理冲突。
- 运行基础校验和回归检查。

主要文件：

| 文件 | 说明 |
|------|------|
| `project.godot` | Godot 项目配置、autoload、版本号 |
| `scenes/game.tscn` | 主游戏场景和关键节点结构 |
| `scripts/game_manager.gd` | 游戏主控制器，负责模块编排 |
| `scripts/game_state.gd` | 全局状态和信号 |
| `README.md` | 当前状态和开发入口 |

主体线程可以改任何文件，但应该尽量保持改动小而明确。

### 2. 战斗核心线程

职责：

- 防御塔逻辑。
- 敌人逻辑。
- 子弹、伤害、状态效果。
- 升级、出售和基础战斗反馈。

主要文件：

| 文件/目录 | 说明 |
|-----------|------|
| `scripts/tower.gd` | 塔基类 |
| `scripts/enemy.gd` | 敌人基类 |
| `scripts/bullet.gd` | 子弹逻辑 |
| `scripts/towers/` | 具体塔 |
| `scripts/enemies/` | 具体敌人 |

注意：

- 不要随意改 `game_manager.gd` 的关卡流程。
- 如果需要新增 UI 展示，先把数据或信号做好，再交给 UI 线程接。
- 新增塔/敌人时要说明数值、定位和与现有内容的差异。

### 3. 地图、波次与数值线程

职责：

- 网格地图。
- A* 寻路和堵路规则。
- 波次配置。
- 经济和关卡压力调平。

主要文件：

| 文件/目录 | 说明 |
|-----------|------|
| `scripts/game_grid.gd` | 网格、封禁区、寻路 |
| `scripts/wave_manager.gd` | 波次生成和倒计时 |
| `scripts/game_manager.gd` 中的 `level_maps` | 当前临时地图数据 |
| `scripts/game_manager.gd` 中的 `level_1_waves` | 当前临时波次数据 |

后续建议：

- 将 `level_maps` 抽到独立数据脚本或资源文件。
- 将波次数据抽到独立数据脚本或资源文件。
- 抽离完成后，这个线程可以更安全地独立工作。

### 4. UI 与体验线程

职责：

- 主菜单。
- HUD。
- 关卡选择。
- 胜利/失败界面。
- 操作提示、选中态、按钮状态。

主要文件：

| 文件/目录 | 说明 |
|-----------|------|
| `scripts/hud.gd` | 游戏 HUD |
| `scripts/main_menu.gd` | 主菜单逻辑 |
| `scenes/main_menu.tscn` | 主菜单场景 |
| `scenes/game.tscn` 中 `UI` 节点 | 游戏内 UI |

注意：

- UI 线程可以显示游戏状态，但不要直接决定游戏规则。
- 如果需要新的状态数据，先通过 `GameState` 信号或公开方法取得。

### 5. 美术资源线程

职责：

- 素材生成、整理和导入。
- 动画帧命名。
- 占位素材替换。
- 视觉风格统一。

主要文件：

| 文件/目录 | 说明 |
|-----------|------|
| `assets/` | 已接入游戏的资源 |
| `ai_assets/` | AI 素材生成管线和提示词 |
| `图片/` | 当前未跟踪素材来源目录，后续需要整理 |

注意：

- 不要直接修改战斗逻辑。
- 新素材应先进入 `assets/` 下清晰命名的目录。
- 导入后要确认 Godot 生成的 `.import` 文件是否需要纳入版本管理。

### 6. 策划与文档线程

职责：

- 维护策划案。
- 记录当前版本目标。
- 维护功能状态表。
- 整理后续路线图。

主要文件：

| 文件/目录 | 说明 |
|-----------|------|
| `docs/奇迹塔防_游戏策划案.md` | 长期设计文档 |
| `docs/开发模块分工.md` | 模块边界和协作规则 |
| `README.md` | 当前项目状态 |

注意：

- 策划可以宏大，但当前版本目标必须小而可验证。
- 文档更新要区分“已经实现”和“计划实现”。

## 分支线程工作流程

1. 明确本次只做一个模块目标。
2. 开始前读取 `README.md` 和本文件。
3. 只修改自己模块的文件。
4. 如果必须改共享文件，先说明原因。
5. 完成后报告修改文件、行为变化和测试结果。
6. 主体线程负责集成、校验和决定下一步。

## 共享文件修改规则

| 文件 | 默认归属 | 修改规则 |
|------|----------|----------|
| `project.godot` | 主体线程 | 只有版本、autoload、输入映射等需要时修改 |
| `scenes/game.tscn` | 主体线程/UI 线程 | UI 节点可由 UI 线程改；核心节点结构由主体改 |
| `scripts/game_manager.gd` | 主体线程 | 分支尽量不改；需要改时只做小范围改动 |
| `scripts/game_state.gd` | 主体线程 | 新增全局状态或信号时必须说明用途 |
| `README.md` | 主体线程/文档线程 | 只记录当前真实状态，不写空泛计划 |

## 当前优先级

1. 稳定基础闭环：造塔、寻路、波次、胜负、升级、出售。
2. 改善操作反馈：按钮状态、提示、命中反馈、失败原因。
3. 整理数据边界：地图、波次、塔、敌人数值从主控制器中逐步抽离。
4. 整理素材目录：将未跟踪素材归档到 `assets/` 或素材源目录。
5. 再扩展纪元内容。

## 什么时候开新聊天框

适合开新线程的情况：

- 一个模块要连续做多轮，比如“只做 UI”或“只做波次平衡”。
- 需要长期保留某个模块的上下文。
- 主体线程已经很长，且当前任务边界清晰。

不适合开新线程的情况：

- 正在改 `game_manager.gd`、`game.tscn` 这类共享文件。
- 需求还不清楚。
- 一次改动横跨多个模块。

第一次开发时，建议先用主体线程推进。等某个模块稳定成形，再把它拆给独立线程。
